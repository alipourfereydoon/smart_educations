# موتور پیشنهاد آموزشی (نمونه)

## ویژگی‌ها

تمام نمره‌ها با `normalize_score` به بازهٔ [۰،۱] نگاشت می‌شوند. در مقیاس پاسخ ۱ تا ۵، تبدیل خطی `(x-min)/(max-min)` است؛ سؤال reverse-scored معکوس می‌شود. `calculate_assessment_values` میانگین هر گروه را می‌گیرد و برای ویژگی بدون پاسخ مقدار پیش‌فرض ۰٫۵ می‌گذارد.

| نام ویژگی | منبع/معنا |
|---|---|
| `motivation` | میانگین انگیزش |
| `attention` | توجه/تمرکز (با احتساب آیتم معکوس) |
| `self_regulation` | برنامه‌ریزی و پایش یادگیری |
| `practice_preference` | ترجیح تمرین عملی |
| `visual_engagement` | در نمونه، جانشین ترجیح تمرین؛ متغیر مستقل اندازه‌گیری‌شده نیست |
| `reading_comprehension` | دستهٔ reading |
| `mathematics_performance` | دستهٔ mathematics |

مدل تنها یکی از کدهای راهبرد را پیش‌بینی می‌کند. قاعده‌های شفاف در `ml_engine/recommender.py` در کنار آن عمل می‌کنند؛ در دادهٔ کم پاسخ، ارجاع انسانی پیشنهاد می‌شود.

## داده‌سازی و آموزش

`training_data.csv` دادهٔ مصنوعی/نمونه برای بازتولیدپذیری دمو است. ستون‌ها هفت ویژگی float و `strategy_label` هستند. هیچ رکوردی را به عنوان کاربر واقعی تفسیر نکنید. اجرا:

```bash
python ml_engine/train_model.py
```

تقسیم train/test با seed ثابت، stratification، RandomForest (class_weight balanced) استفاده می‌شود. مدل، feature names و نسخهٔ `demo-rf-1` در `ml_engine/artifacts/recommender.joblib` ذخیره می‌شوند؛ معیارها و اندازهٔ داده در `metrics.json` ثبت می‌شود.

## ارزیابی و XAI

دقت و classification report در آزمون نگه‌داشته‌شده چاپ/ذخیره می‌شود. برای محصول، accuracy کافی نیست: به تفکیک کلاس precision/recall/F1، confusion matrix، calibration، آزمون زمانی و گروهی، نرخ abstain و اعتبارسنجی خارج از نمونه نیاز است. نمونهٔ کوچک مصنوعی این معیارها را برای تعمیم واقعی معتبر نمی‌کند.

برای توضیح، می‌توان اهمیت ویژگی‌های RandomForest را صرفاً به‌عنوان توضیح کلی گزارش کرد؛ برای هر توصیه، قاعده/دلیل فارسی و ویژگی‌های اثرگذار را جداگانه نشان دهید. اهمیت کلی، علت فردی نیست. از SHAP یا روش مشابه فقط پس از اعتبارسنجی و با توضیح محدودیت استفاده کنید. خروجی باید قابل بازبینی انسانی باشد و برای نمره‌دهی پرمخاطره، تنبیه یا تشخیص سلامت به کار نرود.

## نسخه‌بندی و پایش

ثبت کنید: شناسهٔ artifact/hash، نسخهٔ کد و feature schema، دادهٔ آموزش و provenance، seed، زمان، معیارها و تأییدهای حاکمیتی. `ModelVersion` برای ثبت نسخه در DB وجود دارد؛ مدل artifact باید همراه release منتشر شود و فایل joblib ناشناس را load نکنید (بارگذاری pickle می‌تواند کد اجرا کند). قبل از جایگزینی مدل، schema ویژگی، سازگاری نسخه، خروجی‌ها و rollback را بیازمایید. drift، کیفیت، سوگیری و بازخورد انسانی را پایش کنید و امکان خاموش‌کردن پیشنهاد ML داشته باشید.
